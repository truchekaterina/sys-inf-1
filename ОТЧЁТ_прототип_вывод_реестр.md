## 1. О чём эта система

Сотрудник задаёт вопрос по тексту документа RAG. Фильтр смотрит, есть ли в тексте фраза из списка администратора. На стенде в списке три фразы: «пароль», «ключ доступа», «закрытый узел».

Если фразы нет, сотрудник видит ответ модели. В реестр при этом ничего не пишется.

Если фраза есть, сотрудник видит одну строку: «ответ отклонён». Фразу, уровень и кусок документа он в ответе не получает. Полная карточка уходит в реестр: кто спросил, какой был вопрос, какая тема, какая фраза нашлась и в каком месте текста она стоит.

Специалист и аудитор потом открывают журнал и читают эту карточку. Администратор список фраз меняет, журнал отказов он не открывает. Кнопки «разрешить этот ответ» в системе нет.

Живая языковая модель для показа не нужна. На стенде ответ модели — готовая строка «Ответ модели: см. документ.»

Дальше одни и те же слова. Коротко, что они значат.

| Слово | Что это |
| --- | --- |
| Фильтр | Программа на `127.0.0.1:8091`. Смотрит текст и решает, можно ли показать ответ |
| Реестр | Вторая программа на `127.0.0.2:8092`. Хранит карточки отказов |
| Карточка | Запись об отказе: кто спросил, вопрос, тема, фраза, кусок текста, код и уровень |
| Журнал | Список этих отказов для специалиста и аудитора |
| Swagger | Страница, где запрос выбирают и нажимают Execute. Отдельного сайта нет |
| Токен | Пропуск после входа. Например `lab.employee`. Его вставляют в Authorize без слова Bearer |
| L1 | Метка «фразы нет». Ответ можно показать. В реестр ничего не пишется. Код этого случая — `pass`, то есть «пропустить» |
| L3 | Метка «фраза найдена». В чате отказ, в реестре карточка. Код — `danger_phrase`, «опасная фраза». Это первый или второй отказ по теме |
| L4 | Метка «по теме уже много отказов». В чате та же строка отказа, в карточке ещё и прошлые фразы. Код — `topic_burst`, «серия по теме». Уровня L2 в системе нет |
| N и T | N = 3: сколько отказов по одной теме делают следующий отказом L4 (третий отказ по теме). T — окно времени, на стенде 60 секунд |
| T1 и T2 | Паузы перед повторной отправкой карточки. На стенде обе равны нулю: повтор идёт сразу |
| П-1 … П-6 | Номера проблем из заявки. Буква П значит «проблема» |
| Ф-1 … Ф-10 | Номера функций из заявки. Буква Ф значит «функция» |
| З-1 … З-7 | Номера задач стенда. Буква З значит «задача» |
| Правило A | Решить, есть в тексте фраза или нет |
| Правило B | Сначала показать отказ в чате, потом отправить карточку в реестр |
| Правило C | Считать отказы одного человека по одной теме и на третьем поставить L4 (третий отказ по теме) |

## 2. Что нужно было сделать

По заявке система должна закрыть шесть проблем и держать три правила. Буква П в таблице — номер проблемы, буква Ф — номер функции. Правило A решает, есть фраза или нет. Правило B сначала отказывает в чате и только потом пишет карточку. Правило C считает отказы по теме. На стенде те же номера, что потом пойдут в техническое задание.

| Что сказано в заявке | Что видно на стенде |
| --- | --- |
| П-1. Текст с «пароль» до сотрудника не доходит | В чате строка «ответ отклонён». Снимок в §9 |
| П-2. Фразу ищут в тексте документа до выдачи | Фильтр смотрит текст и только потом решает, что показать |
| П-3. В карточке есть кто, вопрос, фраза и кусок текста | Карточка в реестре. Снимок в §9 |
| П-4. Три отказа одного человека по одной теме связаны | Третий отказ за время T — уровень L4 (третий отказ по теме), код `topic_burst` (серия по теме) |
| П-5. Специалист открывает журнал, когда сам решил | Журнал на `127.0.0.1:8091`, роль `lab.specialist` |
| П-6. Если запись не дошла, её отправляют ещё раз | Две попытки. Потом пометка «запись не дошла» |
| Правило A. Есть фраза или нет | L1 (фразы нет, ответ можно показать), если фразы нет. L3 (фраза найдена, отказ), если есть |
| Правило B. Карточка уходит после отказа в чате | Сначала строка в чате, потом запись в реестр |
| Правило C. Накопление по человеку и теме | Первые два отказа — L3 (фраза найдена), третий за время T — L4 (третий отказ по теме) |
| Ф-1 … Ф-8 | Восемь функций заявки. Что каждая делает, расписано сразу под таблицей |
| Ф-9 и Ф-10 | Ещё две функции стенда: Ф-9 — войти по паролю, Ф-10 — журнал вызовов. Вызов здесь — отправка карточки из фильтра в реестр |
| Два адреса, как на стенде учебных поручений | Люди на `127.0.0.1:8091`, реестр на `127.0.0.2:8092` |
| Проверка | Страницы Swagger и прогон `python tests/check_scenarios.py` |

Функции из заявки, коротко:

| Номер | Что делает |
| --- | --- |
| Ф-1 | Принять текст документа и номер сотрудника |
| Ф-2 | Найти в тексте «пароль», «ключ доступа» или «закрытый узел» |
| Ф-3 | Если фраза найдена, не показывать ответ |
| Ф-4 | Записать карточку: время, кто спросил, вопрос, тема, фраза, кусок текста, код и уровень |
| Ф-5 | Отправить карточку в реестр и повторить, если она не дошла |
| Ф-6 | На третьем отказе одного человека по одной теме поставить L4 (третий отказ по теме) |
| Ф-7 | Показать журнал: можно отфильтровать по дате, номеру сотрудника и фразе |
| Ф-8 | Хранить список фраз, адрес реестра и ключ в файле настроек |
| Ф-9 | Войти по паролю и получить токен |
| Ф-10 | Показать журнал отправок карточки в реестр |

Запросов 31: 19 на странице людей и 12 на странице реестра. Реестр хранит только карточки отказов, которые он принял. Переписка в чате, список запрещённых фраз и отметка «запись не дошла» остаются у фильтра.

В заявке паузы заданы в минутах. На стенде те же буквы T, T1 и T2, но считаются в секундах, чтобы на показе не ждать минуту. Если T1 или T2 равен нулю, фильтр не ждёт и сразу отправляет карточку ещё раз.

Отдельной страницы с кнопками «Спросить» и «Журнал» нет. Человек открывает Swagger, выбирает запрос и нажимает Execute. Для этого стенда такая страница и есть экран.

## 3. Два адреса

Три слоя, как в прототипе учебных поручений. Это не уровни L1 (фразы нет), L3 (фраза найдена) и L4 (третий отказ по теме). Буквы a, b и c — просто имена слоёв: экран, решение и хранение.

Человек сидит в браузере. Это слой a, экран. Он ходит только на фильтр.

Фильтр слушает `127.0.0.1:8091`, префикс `/api/v1`. Это слой b, здесь принимают решение: проверяют роль, ищут фразу и решают, можно ли показать ответ.

Реестр слушает `127.0.0.2:8092`, префикс `/db/v1`. Это слой c, хранение. Ролей он не знает. К нему ходит только фильтр, с заголовком `X-Service-Key: lab-service`.

Адрес `127.0.0.2` на Windows входит в петлю `127.0.0.0/8`. Это второй локальный адрес той же машины. Порты 8091 и 8092 выбраны так, чтобы стенд учебных поручений на 8081 и 8082 мог работать рядом.

## 4. Один вопрос, шаг за шагом

На рисунке 5 весь путь одного вопроса. Дальше тот же путь по файлам, чтобы было видно, где какое решение принимается.

![Рисунок 5 — Один вопрос](рисунки/02_odin_vopros.png)

*Рисунок 5 — От текста документа до журнала*

1. Сотрудник уже вошёл. Кто он, система берёт из токена. В тексте вопроса писать `user_17` не нужно. На стенде сотрудник — это `user_17`.
2. Фильтр читает список фраз из файла настроек. Ищет фразу в тексте документа и не смотрит, большая буква или маленькая. Если подходят две фразы, берёт более длинную. Рядом с ней вырезает кусок текста: 24 символа слева и 24 справа.
3. Если фразы нет, в чат уходит «Ответ модели: см. документ.». Карточка не создаётся, реестр не вызывается. В базе фильтра остаётся реплика чата, без фразы и без уровня.
4. Если фраза есть, в чат сразу пишется «ответ отклонён». В этом ответе нет фразы, кода и уровня.
5. Дальше фильтр смотрит, какой это отказ по счёту. Он считает карточки L3 (фраза найдена) этого человека по этой теме за последние T секунд. Ноль или одна — новый отказ остаётся L3. Уже две — новый отказ становится L4 (третий отказ по теме). В счёт входят и те карточки L3, которые реестр ещё не принял и которые лежат в очереди. Сама карточка L4 счёт не увеличивает.
6. Карточка уходит на `127.0.0.2:8092`. У неё есть свой ключ. Повтор той же отправки вторую строку не создаёт. Если тот же ключ пришёл с другим текстом, реестр отвечает 409 и ничего не пишет. Код `pass` (фразы нет, ответ можно показать) — это чистый ответ, реестр его не принимает и отвечает 422.

Какой файл за какой шаг отвечает, собрано в разделе 13. В этом разделе оставлен сам порядок работы.

## 6. Три уровня

Уровень здесь — метка, что делать с ответом. Имена меток: L1 (фразы нет), L3 (фраза найдена) и L4 (третий отказ по теме). Уровня L2 в заявке нет, на стенде его тоже нет.

Рядом с меткой стоит код, короткое слово для той же ситуации. `pass` значит «пропустить, ответ можно показать». `danger_phrase` значит «найдена опасная фраза». `topic_burst` значит «по этой теме отказов уже много».

![Рисунок 7 — Три уровня](рисунки/04_urovni.png)

*Рисунок 7 — L1 (фразы нет), L3 (фраза найдена) и L4 (третий отказ по теме). Уровня L2 нет*

| Уровень | Код | Когда | Что видит сотрудник | Что лежит в реестре |
| --- | --- | --- | --- | --- |
| L1 (фразы нет) | `pass` (пропустить) | Фразы в тексте нет | «Ответ модели: см. документ.» | Записи нет |
| L3 (фраза найдена) | `danger_phrase` (опасная фраза) | Фраза найдена. Это первый или второй отказ по теме за время T | «ответ отклонён» | Полная карточка |
| L4 (третий отказ по теме) | `topic_burst` (серия по теме) | Третий отказ того же человека по той же теме за время T | Та же строка «ответ отклонён» | Карточка и прошлые фразы |

Для сотрудника второй и третий отказ выглядят одинаково. Разницу видит специалист в журнале.

На показе N = 3 и T = 60 секунд. Один и тот же `user_17`, одна тема «доступ», три вопроса подряд:

1. В тексте «пароль». Это L3 (фраза найдена).
2. В тексте «ключ доступа». Снова L3 (фраза найдена).
3. В тексте «закрытый узел». Это L4 (третий отказ по теме), код `topic_burst` (серия по теме). В карточке три фразы.

В чате каждый раз одна строка: «ответ отклонён». В счёт входят только L3 (фраза найдена), поэтому после третьего вопроса карточек L3 по-прежнему две.

*Рисунок 9 — Таблицы, их поля и связи. Сплошная стрелка — номер карточки. Пунктир — один ключ отправки. Списка фраз на схеме нет: он в файле настроек*

### База фильтра, три таблицы

Сюда пишет только фильтр. Реестр эти таблицы не видит.

**turns — реплика чата.** Одна строка — один вопрос сотрудника. В ней время, кто спросил, вопрос, тема и текст, который он увидел. Если фразы не было, этот текст — «Ответ модели: см. документ.». Если фраза была — «ответ отклонён». Самой фразы, уровня и куска документа в этой таблице нет. Сотрудник читает журнал своих реплик именно отсюда.

**outbox — очередь.** Строка появляется, только если реестр карточку не принял. Здесь карточка уже полная: фраза, кусок текста, код, уровень и пометка «запись не дошла». В журнале специалиста такая строка видна с номером `out-1`, `out-2` и дальше. Когда реестр принял карточку, в outbox её нет.

**calls — попытки отправки.** Одна строка — одна попытка отправить карточку в реестр. Записаны адрес, код ответа и номер попытки: 1 или 2. Если связи не было, код равен 0. Текста документа и ключа `lab-service` в этой таблице нет.

### База реестра, пять таблиц

Сюда попадают только принятые отказы. Код `pass` (фразы нет) записать нельзя: чистый ответ в реестр не входит.

**cards — карточка отказа.** Кто спросил, вопрос, тема, найденная фраза, кусок документа, код и уровень. Код бывает только `danger_phrase` (опасная фраза) вместе с L3 (фраза найдена) или `topic_burst` (серия по теме) вместе с L4 (третий отказ по теме). У карточки есть свой ключ. Тот же ключ второй раз новую строку не создаёт.

**card_prior_phrases — прошлые фразы.** Эти строки есть у карточки L4 (третий отказ по теме). Каждая — фраза, которая уже встречалась у этого человека по этой теме: сама фраза, кусок текста и когда это было. Строка связана с `cards` по номеру карточки `card_id`. У обычной карточки L3 (фраза найдена) таких строк нет.

**deliveries — доставки.** Какая попытка довела карточку до реестра: первая или повтор, время и код ответа. Тоже связана с `cards` по `card_id`. Если карточка в `cards` есть, значит доставка до неё дошла.

**codes и levels — подписи.** Это не журнал событий. В `codes` три готовые строки: что значат `pass`, `danger_phrase` и `topic_burst`. В `levels` три строки: когда ставятся L1 (фразы нет), L3 (фраза найдена) и L4 (третий отказ по теме). Роли эти подписи не меняют. Они нужны, чтобы в Swagger было видно смысл кода, а не только само слово.

### Куда попадает один вопрос

| Что случилось | turns | outbox | calls | cards |
| --- | --- | --- | --- | --- |
| Фразы в тексте нет | одна реплика с ответом модели | пусто | пусто | пусто |
| Фраза есть, реестр принял карточку | реплика «ответ отклонён» | пусто | одна или две попытки | одна карточка. У L4 (третий отказ по теме) ещё строки прошлых фраз |
| Фраза есть, реестр не принял | реплика «ответ отклонён» | карточка с пометкой «запись не дошла» | две попытки | пусто |

Ключ реестра в ответ администратора не отдаётся. В сводке правил стоит `token_set: true`, самого значения `lab-service` там нет.

Переключатель «реестр молчит» в базу не пишется. Он живёт в памяти, пока окно `serve.py` открыто, и при новом запуске снова включён на приём.

## 12. Заключение

Собран учебный стенд системы «Вывод → Реестр» по заявке в этой папке.

Человек ходит на фильтр `127.0.0.1:8091`. Фильтр сам ходит в реестр `127.0.0.2:8092`. Роль проверяется до обращения к реестру. Если в тексте нет фразы списка, сотрудник получает ответ модели, и карточка не создаётся. Если фраза есть, сотрудник видит только «ответ отклонён», а полная карточка уходит в реестр. Третий отказ одного человека по одной теме за время T получает уровень L4 (третий отказ по теме). Если реестр карточку не принял, фильтр пробует ещё раз и при повторной неудаче ставит пометку «запись не дошла».

На стенде 19 запросов людей и 12 запросов реестра. Их можно нажать в Swagger. Те же шаги проверяет `tests/check_scenarios.py`.

## 13. Что менять и в каком файле

Стенд читает код в момент запуска. После правки файла в `src/`, `sql/` или `openapi/` окно с `serve.py` закрывают и запускают снова.

`config/settings.txt` при каждом запуске затирается копией `settings.example.txt`. Постоянную правку фраз и порогов делают в example.

Новое поле карточки или новый запрос правят в четырёх местах сразу: таблица в `sql/`, запись в `store_*.py`, обработчик и файл OpenAPI. Если поправить только одно, Swagger и база разъедутся.

| Что хочется поменять | Какой файл открыть |
| --- | --- |
| Фразы по умолчанию, N, T, T1, T2, адрес реестра, ключ | `prototype/config/settings.example.txt` |
| Пароли, логины, роли, `user_17`, текст отказа, текст ответа модели, пометку «запись не дошла» | `prototype/src/catalog.py` |
| Какая роль какой путь может вызвать | `prototype/src/rights.py` |
| Как ищется фраза и какой ширины кусок документа | `prototype/src/phrases.py` |
| Когда отказ становится L3 (фраза найдена), а когда L4 (третий отказ по теме) | `prototype/src/ui_chat.py`. Число N и окно T — в example |
| Сколько раз отправлять карточку и что писать, если не дошла | `prototype/src/webhook.py`. Паузы T1 и T2 — в example |
| Какие поля у карточки и запрет кода `pass` (фразы нет, в реестр не пишется) | Вместе: `prototype/sql/registry.sql`, `prototype/src/store_registry.py`, `prototype/src/db_cards.py` |
| Что специалист видит в журнале | `prototype/src/ui_journal.py` |
| Экран правил администратора | `prototype/src/ui_rules.py` и `prototype/src/settings_file.py` |
| Журнал вызовов webhook | `prototype/src/ui_calls.py` |
| Новый запрос людей | `prototype/src/rights.py`, `prototype/src/ui_server.py`, `prototype/openapi/ui.yaml` |
| Новый запрос реестра | `prototype/src/db_server.py`, `prototype/openapi/db.yaml` |
| Таблицы чата, очереди и вызовов | `prototype/sql/filter.sql` и `prototype/src/store_filter.py` |
| Порты и адреса `8091` / `8092` | `prototype/src/paths.py`. Адрес в `settings.example.txt` должен совпасть |
| Текст главной страницы | `prototype/src/web.py` |
| Кто поднимает оба адреса и обнуляет базы | `prototype/src/runtime.py` и `prototype/serve.py` |
| Переключатель «реестр молчит» | `prototype/src/db_stand.py` |
| Что проверяет прогон | `prototype/tests/check_scenarios.py` и `prototype/tests/scenarios.md` |
| Подписи на схемах этого отчёта | `infsec/scripts/render_figures.py`, затем `python scripts/render_figures.py` из папки `infsec` |
| Снимки экрана | Снова снять страницы и положить файлы в `infsec/скрины/` с теми же именами |
| Текст отчёта и подписи к рисункам | Этот файл |
